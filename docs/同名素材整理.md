# 同名素材整理（0.5.7）

在“赫朝录音命名器”面板点击 **整理同名素材**。工程需要先保存，不要求打开活动序列。此功能只整理当前项目面板及子素材箱中登记的文件，不扫描时间线、整个硬盘或其他 `.prproj`。

## 使用

1. 点击“整理同名素材”，查看完整来源路径、将使用的新名称和项目面板素材项数量。
2. 检查哪些文件可以改名、哪些文件因离线或特殊结构被跳过。清单可滚动；取消预览不会修改媒体。
3. 点击“确认改名”。文件仍在原目录，命名为 `原名-素材_<32位UUID>.原扩展名`，例如 `镜头01-素材_7f3c9a2e4b1d48f0a6c1e8d2b9f04a77.mp4`。
4. 查看逐文件结果。确认完成且素材在线后正常保存 Premiere 工程，再按原有素材整理/项目管理器流程收集和交接文件；若提示恢复不完整，先核对提示中的文件位置和链接，暂勿保存或再次改名。

比较的是完整文件名，包含扩展名，并统一大小写和 Unicode 规范形式。`片段.MP4` 与 `片段.mp4` 算冲突，`片段.mp4` 与 `片段.mov` 不算。不同路径同名，即使内容相同，也分别生成唯一名字；插件不按内容去重。同一路径重复导入多个项目面板素材项，只改一次文件，并同步这些素材项的名称和链接。

扫描包括项目面板中的所有子素材箱和未上时间线的素材。序列项直接跳过；仅存在于时间线的图形或其他项目面板外的来源不在本次检查范围。素材项重链接后，使用它的时间线片段仍引用同一素材项；不逐条改写片段显示名称，也不把这次结果当作全时间线引用审计。

素材箱还可能包含字幕样式等非媒体条目。0.5.4 根据 PR 的对象转换结果把它们列入跳过清单，不再因它们中止普通媒体扫描；不按“字幕”“样式”等名称关键词判断，真正叫这些名字的视频文件仍会正常检查。素材身份失效、类型转换抛出异常或必要媒体接口不可用时仍会停止，不把读取故障当作非媒体条目。

## 和录音功能的关系

原有录音仍按 `项目名-UUID.wav` 自动命名并移入工程旁的 `Adobe Premiere Pro Captured and Generated`。普通素材的 `-素材_` 标识单独识别，WAV 也不会被“扫描遗漏”重新当作录音处理。

同名整理只在点击时扫描。预览和执行期间暂缓录音监听队列及新的回收检查，关闭后继续；建议停止录制和导出后使用。新增功能不改变录音轮询频率，也不逐文件保存或重写 `.prproj`。

0.5.6 与录音“扫描遗漏”使用同一个重链接函数：调用 Premiere 修改单个素材项的路径、刷新媒体，再读回路径和在线状态。普通素材仍按项目面板汇总同源引用；不会借用录音的自动回收登记，也不要求它出现在时间线上。

普通素材永不登记自动回收。已经在本工程登记自动回收的录音会保留原命名与登记，避免与正在执行的回收任务冲突。即使某个普通文件也有 UUID，单凭名称也不会得到回收权限。录音回收仍独立检查全部时间线引用，不能拿这次仅扫描素材箱的结果证明录音未使用。

## 处理范围

支持普通单文件素材：MP4、MOV、M4V、AVI、MKV、WebM、MPG、MPEG、WMV；WAV、AIF、AIFF、MP3、M4A、AAC、FLAC、OGG、WMA；BMP、JPG、JPEG、PNG、TIF、TIFF、GIF、WebP。格式能否导入、重链接仍取决于 Premiere 本身。

以下情况保留文件并说明原因：

- 离线、正在写入、无权限、不可改媒体路径的文件。
- 带代理的素材，以及同时被其他素材当作代理使用的文件。
- 疑似图片序列：文件名以数字结尾的图片，需要宿主 XMP 明确标记 `videoFrameRate=Still` 才处理。Premiere 25.6 没有独立的图片序列识别 API，未知状态保留；普通照片也可能因此被跳过。
- PSD 分层文件、AE 动态链接、相机素材包及未列出的格式。MXF/MTS/R3D 等不能仅凭扩展名证明没有跨文件依赖，暂不处理。
- 带关联 XMP 文件、符号链接/目录链接、硬链接或无法确认真实路径的素材。
- 已登记自动回收的录音。

如项目面板内发现无法展开的合并/多机位媒体或 AE 动态链接，其隐藏来源可能引用候选文件，整批只允许预览。读取任何素材箱或必要媒体状态失败时也停止，不把部分结果当作完整的项目面板扫描。

## 文件和失败恢复

普通素材只在原目录改名，不复制大视频，不移动到录音目录。使用 UXP `Entry.moveTo(..., { overwrite: false })` 防止覆盖，目标被占用就停止该条；预览后源文件、素材名称或引用变化时需重新扫描。文件锁导致该条未完成，可释放占用后重新扫描；不会在前台不断重试卡住列表。

每个文件作为一个事务：先核对身份和项目面板引用，再改磁盘名称、重链接扫描到的全部素材项，最后同步素材项名称并验证。出错时恢复该文件的原名、原链接和各自原名称。普通文件失败且恢复正常时可继续其他文件；恢复不完整、项目切换、记录写入失败会停止后续。点击“停止后续”会让正在处理的一条先结束，已完成的文件保留新名称。

手动整理会在改名前后分块核对完整 SHA-256。exFAT 外置盘上的文件编号、创建时间可能随改名变化，因此不再要求这些字段跨改名保持一致；在同一路径读取期间，元数据仍须稳定，内容不匹配则停止。每块约 1 MiB，定期让出界面执行时间，不复制大视频；大文件会增加顺序读取时间，面板显示当前校验阶段。宿主缺少分块读取能力时，大文件在改名前停止。自动录音的同盘流程不增加这轮完整读取。

操作前先把旧路径、新路径及原素材项名称写入：

```text
<工程目录>/Adobe Premiere Pro Captured and Generated/素材命名记录/
  <批次ID>-计划.json
  <批次ID>-0001-校验.json
  <批次ID>-0001-结果.json
  ...
```

记录不加入自动回收登记。计划先写，每条文件的校验记录保存改名前完整内容指纹，写入并读回成功后才改名；结果记录保存改名后实际元数据、恢复状态与需核对的位置。记录逐个独立写，不覆盖唯一的恢复清单。断电或进程崩溃后，有计划但无结果的文件需要按映射核对磁盘和 PR 链接；计划或校验文件本身不证明已经完成。记录写入失败不会继续处理后续文件。

这是对真实源文件改名。**其他未打开的工程若共用这些文件，需要重新链接**；本插件不会替它们改 `.prproj`。已错误链接到同名替代文件的素材，改名不能判断或修复来源，应先核对画面/声音。Premiere 的撤销只能影响可撤销的名称动作，不能还原磁盘文件名或媒体路径。全部完成并确认在线后再正常保存工程；恢复不完整时面板不再提示保存或直接重新扫描。JSON 是映射及校验记录，不是素材内容备份，也没有实现一键跨会话撤销。

## 验证状态

已覆盖真实合成文件操作和模拟宿主的多类型冲突、子素材箱递归、多素材项同步、无时间线素材、预览取消、重复点击、停止后续、文件锁、目标竞争、源文件变化、项目切换及失败恢复。构建会核验脚本加载顺序和源/产物哈希。

0.5.0 在真实 Premiere 中发现素材箱扫描报 `item.getId is not a function`；0.5.1 改用反向转换后，用户仍反馈“无法读取素材身份”。0.5.2 取消了根容器的素材身份要求：根容器直接列出内容，子素材箱和媒体保留原始 ProjectItem 读取 ID，不再反向转换。兼容字符串及非负安全整数 ID，同步或异步的素材类型转换；无效 ID、重复素材箱、循环结构和读取错误仍中止扫描。报错附带位置与原因，不把不完整扫描视为没有冲突或没有引用。

0.5.2 后续实机错误定位到视频轨中的文字图形。0.5.3 按用户明确要求把整理范围改成项目面板，移除时间线和嵌套序列遍历；预览与执行复查均使用这一范围。回归覆盖序列接口不可用、仅时间线存在的素材排除、素材箱名称变化拦截，以及不改写时间线片段名。

0.5.3 后续实机遇到 StyleProjectItem，因它无法转换为 ClipProjectItem 而中断。0.5.4 补上非媒体条目分支，预览显示跳过项；真实文件候选继续完成核对、改名和重链接。回归覆盖六个样式与媒体混合、名称伪装、空转换与异常区分、预览后引用变化，以及样式存在时的完整面板批量操作。模拟测试不代表宿主验收通过。

0.5.4 实机扫描已找到同名文件，但目录检查因 UXP 未提供完整 Node.js Stats 接口而将它们全部跳过。0.5.5 不再把缺少 `isSymbolicLink()` 直接当作目录异常：使用 `lstat().isDirectory()` 核对目录类型，并检查可用的链接标志和文件类型位。已识别的链接、非目录、权限错误及类型不可读仍受保护。

0.5.5 后续实机在 exFAT 外置盘上改名后，因文件编号和创建时间变化误判身份失败，回滚重复了同一错误。0.5.6 用完整内容校验跨越改名、保存实际目标元数据，并与录音共用重链接；模拟回归已复现旧故障并覆盖修复、失败恢复及错误提示。

0.5.7 精简主面板和预览窗口布局，保留完整文件名、路径和风险说明。256 项自动测试、构建一致性和三档尺寸的浏览器预览通过；详见 [0.5.7 更新说明](0.5.7更新说明.md)。本地安装、私人素材恢复记录与测试临时文件不包含在公开源码中。

Windows 和 macOS 使用同一套 UXP 代码；macOS 自动回收仍不启用。模拟宿主测试不能替代真实 Premiere：当前版本的真实 UXP 分块读取、改名与媒体重链接，以及 macOS 宿主仍待临时工程验收。`runtime_tested=false`。

宿主接口依据：Adobe [ProjectItem](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/projectitem/)、[FolderItem](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/folderitem/)、[ClipProjectItem](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/clipprojectitem/)、[Metadata](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/metadata/) 和 [UXP Entry](https://developer.adobe.com/premiere-pro/uxp/uxp-api/reference-js/modules/uxp/persistent-file-storage/entry/)。
